## Phase 2 benchmark limits

Synthetic families establish structural algorithm behavior, not utility benefit. Freeze
checks reject changed evaluation inputs; no 5% gain is required. Independent validation
checks every metric; exhaustive optimality is limited to supported problems completed
within the node budget. Restricted-horizon scoring must never be relabeled completed
outage duration. Legacy adapters do not claim exact UI equivalence. Runtime/memory
observations include instrumentation and are separate from deterministic result hashes.
See [G2](planning/V1_1_0_PHASE2.md) for observed checks and approval status.

## Phase 3 findings

The median promotion target was missed: no default optimizer promotion is recommended.
Small fixed search budgets leave large optimality gaps on some cases; FEASIBLE is not
OPTIMAL. Validated fallback protects the declared primary cost, not every fairness or
critical-service metric. Such regressions are retained in the G3 report. Published data
is not a blind holdout; crossed cluster intervals with only five seeds provide limited
design sensitivity, not operational confidence. Missing OR-Tools falls back explicitly.
See [G3](planning/V1_1_0_PHASE3.md).

## Phase 4 findings

Outage-payload permission, acquisition, zero/missing resolution and county-time validity
remain unmet. NOAA report counts cannot substitute for outage coverage or independent
evaluation clusters. No-Go with null predictive metrics prevents unsupported promotion.
The executable checks test software behavior; they cannot certify source rights or real
event reconstruction. Public URLs and revisions may change, so cached response hashes
separate exact replay from new acquisition. See [G4](planning/V1_1_0_PHASE4.md).
