# Execution and handoff

The original planning/engine/browser milestones are complete and superseded by the AEP Data Guide realignment. Current formulas, values and evidence live in [MODEL_SPEC.md](MODEL_SPEC.md), [AEP_REALIGNMENT.md](AEP_REALIGNMENT.md) and [DEMO_FREEZE.md](DEMO_FREEZE.md). Earlier labor interpretation is no longer an implementation target.

## Ownership

One schema/calculation owner maintains `backend/contracts.py`, `backend/engine.py`, source verification and tests. Customer UI consumes generated types and API values. Integration owns API, explanation and customer adapters. Preserve teammate pipeline files and all raw/processed data; do not duplicate their existing guidance rules. These workstreams do not authorize autonomous agent delegation.

## Realignment gates

1. Record requirement matrix before product edits; inspect branch, fetch and review teammate changes. Existing clean freeze commit provides rollback history.
2. Correct AEP person-hours, retain replacement removal scope, disclose open conversion efficiency and crew composition. No duplicate travel/setup.
3. Implement crew controls, reverse asset dependencies, bounded repair release and spatial facility context. Leave ARCOS identity, actual sectionalization and affected facilities unavailable where unsupported.
4. Add explicit session-only customer needs; keep them out of AI and numerical calculations.
5. Recheck full tests, generated types, build, real browser, live Gemini and deterministic fallback. Update current docs and freeze.
6. Review exact diff/status and source integrity. Commit/push only with current authorization; no broad staging or teammate cleanup.

## Remaining evidence work

Operational validation needs measured crew productivity/task concurrency, crew composition, dispatch/storm/clearance/material delays, verified ARCOS→asset/section and facility→electrical attachment, switching feasibility, broader topology reconciliation, calibrated risk/restoration outcomes and official AEP alert/priority rules. These are explicitly open, not chosen convenient defaults. No new ML, weather, RAG or full power-flow scope is required for this bounded prototype.
