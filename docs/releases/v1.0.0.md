# GridGuide v1.0.0 | HackOHI/O 2026 Portfolio Release

> Local draft for owner review. No tag or GitHub Release has been created. Release gates are tracked in the [checklist](CHECKLIST.md); data rights and sensitive history remain unresolved.

GridGuide is an independent outage-concierge prototype built by a three-person team for the AEP AI Outage Concierge Challenge at HackOHI/O 2026, October 24–25. It connects verified source dependencies with transparent restoration scenarios, customer preparation, communication previews, and bounded AI explanations. It is not an official utility deployment or an AEP-endorsed product.

## Preserved hackathon-period implementation

- Customer Overview for one vetted anonymous location, with explainable storm concern, uncertainty, and crew/access scenario controls.
- AEP workbook-based repair person-hours, using the 4.5 multiplier once, separated from a conditional elapsed-time envelope.
- Four-candidate repair-priority comparison with critical-service-aware and customer-impact-focused prototype policies, independent crew scheduling, and dependency-release milestones.
- Preparation guidance, explicit session-only customer declarations, and four preview-only communication stages.
- Source lineage, generalized maps, exact typed joins, complete reverse-membership validation, and missing-evidence abstention.
- Optional Gemini reference selection with server-rendered claims, bound result/revision checks, and offline Standard explanations.

## Technical highlights

- **117,599** indexed premise paths; **40,779** complete source-validated paths. Unresolved paths remain explicit.
- **8,093 physical assets** with complete reverse evidence, within 32,600 syntactically indexed asset/terminal keys. Index coverage is not universal validation.
- Four curated candidates cover **28 unique premise dependencies**, deduplicating 29 memberships.
- The one-versus-23 policy example compares repairs with the same **1.728 repair person-hours**. Its critical-service relationship is a spatial proxy; historical damage matching is a spatial hypothesis.
- One/two crews control independent work; people per crew controls a separate time-envelope assumption. Blocked work withholds full completion and defers dependent tasks.

## Known limitations and release prerequisites

There is no live outage or utility-confirmed restoration feed, calibrated outage probability, confirmed critical-facility electrical attachment, or established switching feasibility. Operational productivity, dispatch/clearance/material delays, and actual restoration outcomes are unavailable. The time envelope is not a calibrated confidence interval or guaranteed bound. Potential premise releases are not confirmed restored customers. Notifications are previews, and the four-candidate scenario is not system-wide optimization.

Full execution requires authorized access to the pinned AEP data. Raw and derived data remain tracked in the existing public repository and history; public upstream access does not establish redistribution rights. Resolve the [audit findings](PUBLIC_RELEASE_AUDIT.md), contributor consent, complete team credit, and license decisions before publishing this official release. No project-wide license is granted by this draft.
