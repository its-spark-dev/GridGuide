# GridGuide v1.1.0 — release candidate

**Prepared for independent G9 review; not tagged, published or deployed.**

GridGuide now offers a reproducible fictional restoration decision-support demonstration
separate from the original AEP challenge application. It connects customer dependency
inspection and offline preparedness with Python-owned policy comparisons, explicit human
review and reproducible JSON/text exports. It remains a research/portfolio project.

## What changed

- Six independently authored customer scenarios and 18 prepared milestones expose
  completed, blocked and unresolved power paths without invented utility connectivity.
- An explicitly installed offline kit and explicitly saved synthetic snapshots survive
  browser restart without networking. Saved results are immediately historical.
- Eight operator microcases compare FIFO, customer-count, release/person-hour and
  critical-proxy-first. Bounded precedence overrides recompute/validate in Python;
  changes invalidate review. Optional CP-SAT is a frozen validated experiment.
- Versioned evidence audits, frozen benchmarks and conditional simulation reports make
  both improvements and unsuccessful research conclusions reproducible.
- An explicit 38-file allowlist, dependency notices/hash locks, one-origin nonroot
  container and source-free CI support independent reproduction without original data
  or AI credentials. Standard explanations are deterministic; external AI is disabled.

## Scientific interpretation

The fixed release/person-hour baseline stays recommended. **The 5% median promotion
target failed.** Combined best-of-four plus CP-SAT mean gain versus fixed was **0.351%**;
incremental mean beyond best-of-four was **0.174%**. Different denominators make these
non-additive. Secondary critical-service/fairness regressions, limited cluster-bootstrap
interpretation and the absence of a blind holdout remain explicit.

G4 is an evidence-bounded **No-Go**: no validated probability model or predictive
performance. NOAA context is not an outage label; missing is not zero; permissions,
outcome coverage and real-data split validation remain unresolved/unexecuted. New research
needs a new evidence gate. G5 reports assumption-based fixed-timetable delay propagation,
**195 stable / 15 unstable** convergence combinations, and no empirical calibration or
verified cross-platform equivalence. Its detailed uncertainty UI is deferred.

Read the [final evidence report](../benchmarks/v1.1.0.md) for definitions, denominators,
all outcomes and reproduction links. Passing tests does not prove utility benefit.

## Installation, versions and migration

Use the [tested reproduction guide](../REPRODUCING_V1_1.md) and standalone `deploy/README.md`.
The public package needs Python 3.12, or Docker; Node is only needed to build it. The
original challenge-local application still requires authorized pinned source files.

Product metadata is **1.1.0**, with release-candidate status in the public readiness
endpoint and UI. Historical numerical/evidence/schema IDs remain unchanged; legacy API
composition version labels retain their original scope. No generated types are hand-edited.
New snapshots record app 1.1.0; validated `v1.1-phase6` snapshots remain readable under
`preparedness-snapshot-v1`. Unknown versions/fields remain rejected. Worker cache hashes
are rebuilt from exact current assets and only the owned preparedness cache migrates.
Review records remain session-local unless explicitly exported; checksums are not signatures.

## Security, privacy and scope

No protected source records, identities, precise geometry, private declarations, `.git`,
credentials or provider code are distributed. This does not remediate source material
already in repository history. Browser storage may be denied/evicted; a compromised
same origin defeats client-side trust. Testing covers Chromium, not all browsers.
Detailed manual VoiceOver observations remain missing; automated accessibility tests
are not a substitute or a certification.

The public runtime fixes the identified Range-serving issue and retains five unique
Starlette advisories with documented scope mitigations/non-reachability. Three moderate
npm findings remain in the excluded build toolchain. OS/container CVE scanning is
**unexecuted** because the available Docker Scout requires login. No vulnerability-free
or production-security claim follows. See [G8 dispositions](../planning/V1_1_0_PHASE8.md)
and the [fresh G9 evidence](../planning/V1_1_0_PHASE9.md).

Before any future public hosting, complete a current OS/container vulnerability assessment
and review HTTPS, allowed-host, reverse-proxy, slow-client and resource-limit controls.
G8 approval authorized integration of preparation infrastructure only.

Supported use: local education, engineering review, reproducible synthetic experiments
and portfolio demonstration. Non-goals: field dispatch, switching, live outages/ETRs,
real alerts, arbitrary addresses, unrestricted optimization, calibrated predictions,
accounts, public hosting or operational safety certification.
