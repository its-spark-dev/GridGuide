# GridGuide v1.1.0 — Explainable Outage & Restoration Planning

GridGuide's final stable portfolio release brings together its original map-centered
dashboard, practical outage preparation and reproducible restoration decision review.
Explore **Overview → Prepare & alerts → Grid insights**, inspect the evidence behind a
result, and see what changes when repair dependencies constrain a plan.

Built by three teammates at **HackOHI/O 2026, October 24–25**, GridGuide preserves that
foundation while adding a standalone fictional demonstration and a documented engineering
and research record. This is a local portfolio release, with no hosted service, live
utility integration or production certification.

## Two clearly separated experiences

**The preserved challenge-local application** uses authorized, pinned challenge sources.
Overview presents an explainable, uncalibrated concern band and conditional restoration
envelope. Prepare & alerts offers tailored guidance and four communication previews;
messages are never sent. Grid insights retains four distinct geographic candidates:
Golden upstream fuse, Golden transformer, Historical fuse replay and Critical-context
fuse. Generalized equipment/customer areas, optional attributed OpenStreetMap tiles,
crew planning and transparent policy tradeoffs remain available in that mode.

**The source-free fictional package** needs no challenge data, API key or external AI.
It preserves the dashboard identity and navigation while providing:

- Six independently authored customer scenarios and 18 prepared milestones, with
  power-path inspection and explicit completed, blocked and unresolved states.
- A generic preparedness kit and explicitly saved historical fictional snapshots that
  can reopen offline after browser restart. There is no browser numerical engine.
- Eight operator cases comparing FIFO, customer-count, release/person-hour and
  critical-proxy-first policies under identical Python-owned assumptions.
- Bounded, independently validated precedence overrides, explicit review invalidation,
  and sanitized JSON/text exports that can be independently replayed.
- A deterministic 47-file package, dependency hash locks/notices, source-free CI and a
  tested local nonroot container path.

The fictional package has no geographic utility map, household predictor, arbitrary
crew/access recalculation or tailored communication service. Unknown completion remains
unavailable. Optional CP-SAT displays only frozen, validated experimental results.

## What the research established

The strongest fixed **release/person-hour baseline remains the default**. The
preregistered **5% median optimization promotion target failed**. Combined best-of-four
incumbent plus CP-SAT achieved **0.351% mean improvement** against that fixed baseline;
incremental mean improvement beyond per-instance best-of-four was **0.174%**. These
comparisons have different denominators and are not additive. Case-level regressions,
critical-service/fairness tradeoffs, limited cluster-bootstrap interpretation and absence
of a blind holdout remain disclosed.

Outage-risk research concluded an evidence-bounded **G4 No-Go**. No trained predictor,
outage probability or predictive performance is claimed. NOAA storm context is not an
outage label, missing observations are not zero, and data permissions, coverage and
unexecuted real-data split validation remain explicit. Reopening requires a new versioned
evidence review and data-quality gate; this is not universal public-data infeasibility.

G5 simulation is **assumption-based fixed-timetable delay propagation**, not adaptive
dispatch or empirically calibrated restoration confidence. All **195 stable and 15
unstable** convergence findings remain, with diagnostics and same-environment numerical
checksums. Cross-platform bitwise equivalence is unverified; detailed uncertainty UI
is deferred. Completed customer-hours, restricted 168-hour customer-hours and
unresolved/censored outcomes retain their separate meanings.

The [final evidence report](https://github.com/its-spark-dev/GridGuide/blob/v1.1.0/docs/benchmarks/v1.1.0.md)
preserves every outcome and links to frozen manifests, methods and reproduction commands.
Stable release status does not turn these findings into utility performance claims.

## Download and run locally

Download **gridguide-v1.1.0-public.zip** and **SHA256SUMS** from this Release. Check
`shasum -a 256 -c SHA256SUMS` (Linux: `sha256sum -c SHA256SUMS`), compare with the
[stable package manifest](https://github.com/its-spark-dev/GridGuide/blob/v1.1.0/docs/releases/v1.1.0/package.json),
then follow the reproduction guide's exact-tree inspection before starting.

From the clean extraction, with Python 3.12:

```sh
python3.12 -m venv /tmp/gridguide-runtime
/tmp/gridguide-runtime/bin/pip install --require-hashes -r deploy/requirements.lock
PYTHONDONTWRITEBYTECODE=1 /tmp/gridguide-runtime/bin/python deploy/serve.py
```

Open **http://127.0.0.1:8000/**. Keep environments, exports and downloads outside the
immutable extraction. Installation requires network access; installed operation needs
no external service. Docker and independent replay instructions are in the guide.

`/ready` reports **product_version `1.1.0` / release_status `stable`**. Numerical model,
policy and schema identifiers are unchanged. Existing validated `v1.1-phase6` snapshots
remain readable; unknown versions/fields are rejected. Only the owned preparedness
cache migrates. The approved demonstration and screenshots retain their authentic
candidate-era footer and original hashes; stable finalization changes status text only.

**Download boundary:** only the explicitly attached standalone ZIP is source-free.
GitHub's automatic **Source code (zip/tar.gz)** archives contain original challenge
material. Neither this release nor its isolated package remediates historical repository
exposure or creates a software/data redistribution license.

## Security, privacy and scope

The standalone ZIP excludes original customer/facility records, precise geometry,
private declarations, `.git`, credentials and provider code. Browser storage may be
denied or evicted; same-origin compromise defeats client-side trust. Checksums/replay
establish internal consistency, not authenticated identity or tamper-proof audit history.
Verification covers Chromium; detailed manual VoiceOver observations and broader browser
coverage remain unverified. Automated accessibility checks are not a certification.

Five retained Starlette advisories have documented scope-specific mitigations or
non-reachability arguments. Three moderate npm affected-package findings remain in the
excluded build toolchain. OS/container CVE scanning remains **unexecuted**; no claim of
a vulnerability-free image follows. See the
[G8 dispositions](https://github.com/its-spark-dev/GridGuide/blob/v1.1.0/docs/planning/V1_1_0_PHASE8.md)
and [stable verification record](https://github.com/its-spark-dev/GridGuide/blob/v1.1.0/docs/releases/v1.1.0/FINALIZATION.md).
The silent recording, minor final-caption clipping and historical media limits remain.

Supported use is local education, engineering review and portfolio demonstration.
There is no real alert delivery, live forecast/ETR, field dispatch, switching advice,
arbitrary-address lookup or operational safety certification. No hosting is part of
this release. Any future public exposure requires a current OS/container assessment,
host-specific HTTPS/allowed-host/proxy/slow-client/resource review and separate authorization.
